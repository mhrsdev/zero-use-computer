更新如何进行

  1. 服务器启动几分钟后（update.check_after_mins），此后每隔 check_every_mins（或 check_every_hours），它会向 GitHub 查询仓库的最新版本。电脑上的所有服务器共用一个计时，因此不会重复查询。
  2. 较新的版本会被下载，并与 GitHub 为该文件提供的 SHA-256 进行校验。没有校验和的版本不会被接受。下载的程序会用 --version 运行一次，确认版本与声称的一致。
  3. 然后等待。它只在服务器启动时安装，绝不会在智能体可能正在工作时安装：电脑重启后（restart，默认）、下次启动时（start），或仅在你运行 computer-use-mcp update --install 时（manual）。

选择更新方式

  • 从不：在更新页面将其关闭。不检查也不下载任何内容。
  • 频繁：最短每 5 分钟一次。GitHub 允许每个地址每小时 60 次匿名请求，而没有发现新版本的检查几乎没有开销，因为只询问“是否有变化？”。如果 GitHub 要求放慢，程序会等待一小时。
  • 保持不动：固定某个版本，就只接受该版本；跳过某个版本，就永不安装它。
  • 预发布版：prerelease 通道也接受 GitHub 标记为预发布的版本。

回退

安装更新时，被替换的程序会保留下来（只保留一个）。回退会把它重新装回，并将 update.skip_version 设为你刚离开的版本，以免再次下载。在终端中：computer-use-mcp update --rollback。已在运行的客户端会继续使用旧程序，直到重新启动。
