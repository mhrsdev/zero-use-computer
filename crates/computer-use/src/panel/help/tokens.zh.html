哪些内容消耗 token

对一般任务而言，大致按以下顺序有三项：

  • 图片。一张图片按 宽 × 高 ÷ 750 个 token 计算。1280 px 的 16:9 整屏约为 1,230 个。
  • 工具列表，随每次请求发送。使用 lean 描述时，模型初始可见的工具集约占 2,200 个 token；工具管理器会把其余工具挡在外面，直到模型请求。
  • 树，即屏幕内容的文本。繁杂的窗口可能有数千个 token；之后的查看只发送变化的部分。

可以调整什么

  • 图片尺寸（screenshot.max_dimension）：影响最大的设置。用 1024 代替 1280，图片 token 约少三分之一，图中的文字也会变小。
  • 何时发送图片（screenshot.attach）：auto 在首次查看窗口、发生较大变化或树信息稀少时发送一张。always 最贵；never 让智能体只依靠树。
  • 智能与自适应图片：当树已经说明了变化的内容，或者智能体已多次查看某个应用却从未用到像素时，就不附加图片。两者默认开启。
  • 树的大小（tree.max_nodes、tree.max_tokens）：更大的树会先折叠，再截断。折叠的部分仍然可以查找。
  • 工具：工具列表显示了每个工具的开销。工具管理器设为 dispatch 时，模型从基础工具开始，其余工具按名称查找。
  • 减少往返：智能体的 batch 工具可在一次调用中执行多个已知步骤。

快捷方法

低 token 配置方案会替你设置图片和树的限制；“均衡”会把它们恢复原样。实测数据（及测量方法）见 README 的基准测试部分。这些数据是在没有提示缓存的情况下估算的，因此应视为不同设置之间的对比，而不是账单：模型有自己的计数方式，缓存也会让重复内容更便宜。
