How an update happens

  1. A few minutes after a server starts (update.check_after_mins), and then every check_every_mins (or check_every_hours), it asks GitHub for the latest release of the repository. Every server on the computer shares one clock, so two of them never ask twice.
  2. A newer release is downloaded and checked against the SHA-256 GitHub gives for the file. A release with no checksum is not taken. The downloaded program is run once with --version to see it is the version it says.
  3. It waits. It is put in place only when a server starts, never while an agent may be working: after the computer restarts (restart, the default), at the next start (start), or only when you run computer-use-mcp update --install (manual).

Choosing how it goes

  • Never: switch it off on the Updates page. Nothing is looked for or downloaded.
  • Often: every 5 minutes is the shortest. GitHub allows 60 anonymous requests an hour for each address, and a look that finds nothing new costs nearly nothing, because only "has it changed?" is asked. If GitHub says to slow down, the program waits an hour.
  • Stay put: pin a version to take only that one; skip a version to never take it.
  • Pre-releases: the prerelease channel also takes releases GitHub marks as pre-releases.

Going back

When an update goes in, the program it replaces is kept (one only). Go back puts it in place again, and sets update.skip_version to the one you left so it isn't downloaded again. From a terminal: computer-use-mcp update --rollback. Clients already running keep the old program until they start again.
