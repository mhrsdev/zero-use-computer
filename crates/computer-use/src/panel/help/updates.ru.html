Как происходит обновление

  1. Через несколько минут после запуска сервера (update.check_after_mins), а затем каждые check_every_mins (или check_every_hours) программа запрашивает у GitHub последний релиз репозитория. Все серверы на компьютере пользуются одними часами, поэтому два сервера никогда не спрашивают дважды.
  2. Более новый релиз скачивается и сверяется с SHA-256, который GitHub указывает для файла. Релиз без контрольной суммы не берётся. Скачанная программа один раз запускается с --version, чтобы убедиться, что это заявленная версия.
  3. Обновление ждёт. Оно устанавливается только при запуске сервера, никогда — пока агент может работать: после перезагрузки компьютера (restart, по умолчанию), при следующем запуске (start) или только когда вы выполните computer-use-mcp update --install (manual).

Как настроить

  • Никогда: выключите обновления на странице Обновления. Ничего не проверяется и не скачивается.
  • Часто: самый короткий интервал — 5 минут. GitHub разрешает 60 анонимных запросов в час с каждого адреса, а проверка, не нашедшая ничего нового, почти ничего не стоит, потому что спрашивается только «изменилось ли?». Если GitHub просит притормозить, программа ждёт час.
  • Оставаться на месте: закрепите версию, чтобы брать только её; пропустите версию, чтобы никогда её не брать.
  • Пре-релизы: канал prerelease берёт также релизы, которые GitHub помечает как пре-релизы.

Откат

Когда устанавливается обновление, заменяемая программа сохраняется (только одна). Откат возвращает её на место и записывает в update.skip_version версию, с которой вы ушли, чтобы она не скачалась снова. Из терминала: computer-use-mcp update --rollback. Уже запущенные клиенты пользуются старой программой, пока не перезапустятся.
