Two pointers, and they are not the same

The agent has a pointer of its own, drawn on the screen by the overlay. Your real mouse pointer is yours: most actions don't use it at all, because they press controls through the accessibility interface. When an action does need the real mouse (a click at x/y, a drag), the program moves it, then puts it back where you left it (restore_pointer).

The agent's pointer

Six pointers come with it: crystal, paper, jelly, ice, metal and orbit, plus the plain arrow (classic). Random picks one for each session, and a different one for each agent working at once. Each clicks its own way: the jelly squashes, the ice drips, the paper folds, the orbit's pearl runs round its ring. Choosing one stops the dice. To give particular agents particular pointers, write agent_cursors in the settings file (Settings file), for example { codex = "metal" }.

With Cursor motion on, the pointer leans into its moves, leaves a trail of its own material and breathes while it waits. Show keys puts pressed keys beside it as keycaps, and typed text runs out under its name tag.

The real mouse

With Natural mouse on, the real mouse moves like a hand: along a gentle curve, quick to start and slow to settle, with a faint tremor (and, if you ask for it with Mouse overshoot, now and then a touch past the target and back). Some apps can tell a mouse that teleports from a person's, so this is on by default. It travels only the last 70 to 140 px of the way, because an app sees the pointer only over its own window; the rest of the way would only take your mouse from you for longer. Drags always go straight, since a drag can draw a line.

Path styles

Hand (a bow to one side with a tremor), sine (a wave across the way), arc (a circle's arc), spring (past the target and back, settling) and spiral (in to the target). Mixed picks one at random for each move. The previews on Pointer and Real mouse are made by the same code that moves the mouse, so each press of "Another set" is a fresh sample.
