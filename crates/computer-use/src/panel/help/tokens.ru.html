What costs tokens

Three things, in about this order for a typical task:

  • Pictures. A picture counts as width × height ÷ 750 tokens. A whole 16:9 screen at 1280 px is about 1,230.
  • The tool list, sent with every request. The set the model starts with costs about 2,200 tokens with the lean descriptions; the tool manager keeps the rest out until the model asks for them.
  • Trees, the text of what is on screen. A busy window can run to thousands of tokens; later looks send only what changed.

What to turn

  • Picture size (screenshot.max_dimension): the biggest lever. 1024 instead of 1280 is about a third fewer image tokens, and the text in the picture gets smaller.
  • When pictures come (screenshot.attach): auto sends one for the first look at a window, a big change or a sparse tree. Always is the most expensive; never leaves the agent to the tree.
  • Smart and adaptive pictures: leave a picture out when the tree already says what changed, or when the agent has looked at an app a few times without ever using pixels there. Both are on.
  • Tree size (tree.max_nodes, tree.max_tokens): bigger trees are folded, then cut. Folded parts stay findable.
  • Tools: Tool list shows what each costs. With the tool manager on dispatch the model starts with the base tools and finds the rest by name.
  • Fewer round trips: the agent's batch tool runs several known steps in one call.

The quick way

The Low tokens profile sets the picture and tree limits for you; Balanced puts them back. The measured figures (and how they were measured) are in the benchmark section of the README. They are estimates without a prompt cache, so read them as a comparison between settings, not as a bill: your model counts its own way and the cache makes repeats cheaper.
