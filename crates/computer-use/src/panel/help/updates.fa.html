به‌روزرسانی چگونه انجام می‌شود

  1. چند دقیقه پس از راه‌اندازی یک سرور (update.check_after_mins)، و سپس هر check_every_mins (یا check_every_hours)، تازه‌ترین انتشار مخزن را از GitHub می‌پرسد. همه‌ی سرورهای روی رایانه یک ساعت مشترک دارند، پس دو سرور هرگز دو بار نمی‌پرسند.
  2. انتشار تازه‌تر دانلود و با SHA-256 که GitHub برای فایل اعلام می‌کند بررسی می‌شود. انتشاری که checksum ندارد پذیرفته نمی‌شود. برنامه‌ی دانلودشده یک بار با --version اجرا می‌شود تا معلوم شود همان نسخه‌ای است که ادعا می‌کند.
  3. منتظر می‌ماند. فقط وقتی یک سرور راه‌اندازی می‌شود نصب می‌شود، هرگز وقتی ممکن است ایجنتی در حال کار باشد: پس از راه‌اندازی دوباره‌ی رایانه (restart، پیش‌فرض)، در راه‌اندازی بعدی (start)، یا فقط وقتی خودتان computer-use-mcp update --install را اجرا کنید (manual).

انتخاب شیوه‌ی کار

  • هرگز: آن را در صفحه‌ی به‌روزرسانی‌ها خاموش کنید. هیچ چیز جستجو یا دانلود نمی‌شود.
  • اغلب: کوتاه‌ترین بازه هر 5 دقیقه است. GitHub برای هر نشانی ساعتی 60 درخواست ناشناس را می‌پذیرد، و بررسی‌ای که چیز تازه‌ای پیدا نکند تقریباً هزینه‌ای ندارد، چون فقط پرسیده می‌شود «آیا تغییر کرده؟». اگر GitHub بگوید آهسته‌تر، برنامه یک ساعت صبر می‌کند.
  • ماندن روی یک نسخه: نسخه‌ای را ثابت کنید تا فقط همان گرفته شود؛ نسخه‌ای را رد کنید تا هرگز گرفته نشود.
  • پیش‌انتشارها: کانال prerelease انتشارهایی را هم که GitHub پیش‌انتشار علامت زده می‌گیرد.

بازگشت به نسخه‌ی قبل

وقتی به‌روزرسانی نصب می‌شود، برنامه‌ای که جایگزین شده نگه داشته می‌شود (فقط یکی). بازگشت آن را دوباره سر جایش می‌گذارد و update.skip_version را روی نسخه‌ای که از آن برگشتید تنظیم می‌کند تا دوباره دانلود نشود. در ترمینال: computer-use-mcp update --rollback. کلاینت‌هایی که از قبل در حال اجرا هستند تا راه‌اندازی دوباره همان برنامه‌ی قدیمی را نگه می‌دارند.
